# IBC interfaces

These IDLs are generated by Anchor from
[akash-network/ibc-contracts at 0da3165d8428a1b7792cc17551ecd1d3985761e6](https://github.com/akash-network/ibc-contracts/tree/0da3165d8428a1b7792cc17551ecd1d3985761e6/ibc-solana).
That revision already includes signature batches, monotonic latest height,
consensus pruning and open relaying. No patches are applied by node.

`npm run setup:light-client` compares generated IDLs with these committed
interfaces. Regenerate through the owning IBC Anchor build when updating the
pin; never hand-edit a generated IDL. Production program-ID changes follow
[the launch procedure](../docs/deploy-program.md).
The source programs are `ibc-solana/programs/ics07-tendermint` and
`ibc-solana/programs/access-manager`, both Apache-2.0 licensed.

AKT uses Anchor's `declare_program!` in the separate
`programs/akt-solana/ics07-tendermint-interface` crate to generate membership
CPI and account decoding from the Tendermint IDL. The separate crate keeps
verifier errors out of AKT's generated IDL. No signature or Merkle verification
code is copied into AKT.

The IDL address is used by local tests. The bridge stores its authorized
deployment address during configuration and validates account owners and PDAs
against it. A production deployment may use a different ID with the same ABI;
its binary must be built for that ID and reviewed separately.
